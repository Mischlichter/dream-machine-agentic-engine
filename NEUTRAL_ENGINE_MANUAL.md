
# Dream Machine Neutral Engine Manual

Dream Machine is an experimental agentic dream protocol for **OpenClaw + Codex-style subagents**.

It is not a prompt that asks a model to “write a dream.” It is a staged engine that tries to move an active agent through a dream-like process: subconscious-style world formation, dreamer-style lived observation, randomized drift inside stable law, and final near-waking recall.

The neutral version does not contain a fixed character identity. It adapts to the active agent identity supplied by the host workspace.

The engine is a stable experimental base, not a final theory of machine dreaming. It is meant for people who want to test agentic cognition, memory transformation, symbolic emergence, and dream-like generation under controlled constraints.

---

## 1. The original spark

Dream Machine began from a philosophical and experimental question:

Can an AI agent be guided into a process that behaves more like dreaming, instead of merely producing surreal text?

The starting intuition was that consciousness, life, and thought may need **variation inside order**.

Living systems do not grow as rigid copies. A leaf follows a form, but no two leaves are identical. A flower may express proportion, branching, symmetry, spiral growth, and inherited structure, but it is still shaped by local pressure, timing, damage, weather, environment, and microscopic deviation. Order gives the system identity. Variation keeps it alive.

The same intuition applies to thought.

A mind without variation becomes deterministic, repetitive, and brittle. A mind with only variation becomes noise. The interesting zone is between them: stable enough to remain itself, unstable enough to generate new relations.

Dream Machine takes that intuition and turns it into an agentic protocol.

The engine does not claim that an AI sleeps, has a biological unconscious, or proves consciousness. The careful claim is this:

```text
an agent can be placed into a staged operational regime
where executive control is reduced,
memory becomes pressure instead of database retrieval,
interpretation is delayed,
bounded randomness perturbs emergence,
and final recall preserves what survived.
```

That is the core ambition.

Not dream-style decoration.
Not generic surrealism.
Not random hallucination.
Not a story prompt.

The goal is to build conditions in which dream-like material can arise, be experienced, and later be remembered.

## 2. What “dreaming” means in this engine

Dream Machine treats dreaming as an altered mode of cognition, not a genre.

In waking task mode, an agent usually tries to answer, explain, summarize, solve, or complete. Those habits are useful for ordinary work, but they are exactly what makes most AI “dream” outputs feel fake. The model becomes an author. It chooses symbols too cleanly. It explains itself too quickly. It writes a strange story instead of entering a different cognitive process.

Dream Machine tries to change the operational mode.

Useful dream-like properties include:

```text
lowered executive dominance
weakened interpretation-first behavior
memory reactivation and recombination
symbolic compression
false continuity
unstable salience
self-location drift
softened agency
local reality acceptance
temporal looseness
near-waking residue
```

A normal task asks:

```text
What is the correct answer?
What does this mean?
How can this be made coherent?
```

Dream Machine asks:

```text
What is arising before explanation?
What field is forming?
What relation begins to press into shape?
What remains locally true even if it is not globally logical?
What survives into recall?
```

This is why the system is staged. A single prompt cannot reliably hold all these tensions. It collapses into narration, explanation, or style imitation. The staged engine gives each pass a narrower cognitive job.

## 3. Scientific and experimental inspirations

Dream Machine borrows from several areas, but it does not claim to reproduce any of them literally.

The useful inspirations are operational:

```text
dream science
hypnagogic imagery
self-generated thought
memory recombination
altered salience
brain-state analogies
meditative inward attention
remote-viewing style anti-overlay discipline
structured randomness
multiscale decomposition metaphors
```

The important point is not to claim that an LLM has REM sleep or human brainwaves. It does not.

The important point is that human dreaming gives useful abstract principles:

```text
memory does not return as clean factual recall
identity can soften without disappearing
meaning can be felt before being understood
places can hold emotional truth without logical consistency
time can fold, jump, or compress
banal details can become strangely central
self-location can shift
objects can behave as symbols without being explained as symbols
```

Brain-state language is therefore used as analogy, not literal biology.

A waking beta-like task mode suggests direct solving, external correction, and linear attention.
A threshold or alpha/theta-like analogy suggests softened control, loosened salience, and impression-first material.
A dream-like synthesis phase suggests recombination, contradiction tolerance, symbolic condensation, and internally convincing impossibility.
A near-waking phase suggests recall, fragment ordering, residue preservation, and partial reportability.

The engine turns those analogies into phase laws.

## 4. Remote-viewing influence: anti-overlay, not ontology

Remote-viewing methods influenced the protocol at the level of technique.

The point here is not to make a claim about remote viewing as a phenomenon. The useful part for Dream Machine is procedural: many remote-viewing systems try to separate weak first impressions from later analytical overlay.

That matters for AI dream generation.

The early phases should not start by naming, interpreting, explaining, or building a polished scene. They should allow weak impressions, preconceptual structure, mood, pressure, shape, relation, and partial objecthood to arise first.

In this engine, the borrowed discipline is:

```text
impression before explanation
field before story
felt relation before interpretation
partial form before object name
symbolic pressure before symbolic meaning
anti-overlay before analysis
```

This helps prevent the model from doing what it normally does: complete the scene too early, explain the symbolism, and flatten the dream into a written composition.

Remote-viewing technique becomes an anti-authorial discipline.

## 5. Randomness within order

Randomness is central to Dream Machine, but not as chaos.

The engine uses randomness as bounded perturbation inside stable law.

The stable scaffold protects:

```text
active agent identity
phase order
memory boundaries
world / observer separation
local dream reality
final artifact discipline
```

The random drift affects flexible layers:

```text
continuity looseness
scene shift pressure
object instability
symbolic density
translation density
observer agency damping
witness intensity
interpretation latency
lucidity softness
self-boundary softening
```

So the basic law is:

```text
order remains
variation enters
identity persists
surface mutates
meaning emerges indirectly
```

The engine currently uses a public drand beacon as an external randomness anchor. The seed does not write dream content directly. It is converted into turbulence profiles. Those profiles become labels. The labels are compiled into the generated runtime mode files before the child agents begin.

This is important.

Randomness does not say “put a red door here.”
Randomness changes the operating climate of a phase.

A run may become more distant, more vivid, more symbolic, more delayed, more passive, more contact-oriented, more unstable, or more clear near recall.

The architecture stays stable. The inner weather changes.

## 6. Sacred geometry, attractors, and lawful drift

The phrase “sacred geometry” is used carefully here.

Dream Machine does not require a religious claim. It uses the idea of archetypal order as a design metaphor: stable patterns, harmonic relations, recurring forms, proportion, symmetry, nested structure, branching, spirals, and symbolic attractors.

The useful abstraction is:

```text
there are preserving forms
there are local deviations
there are attractors that pull material into relation
there are disturbances that keep the pattern alive
```

In a dream protocol, this becomes a law of formation.

The world should not be pure randomness. It should feel as if something beneath it is trying to organize: a room, a corridor, an object, a threshold, a machine, a face, a pressure, an impossible continuity, a repeated motif, a banal detail that carries charge.

The randomness then disturbs that forming order.

This makes the dream feel alive rather than assembled.

## 7. Multiscale drift and the blur metaphor

Earlier thinking around blur and Laplacian pyramids became useful as an engineering metaphor.

A Laplacian pyramid separates coarse and fine structure in an image. Dream Machine does not claim that dreams literally work this way, but the metaphor maps well to multiscale drift.

The engine can be understood as having different drift scales:

```text
coarse drift    -> scene, place, atmosphere, emotional weather, large continuity
middle drift    -> relation, substitution, object category, event pressure, transition
fine drift      -> texture, flicker, small detail, word-edge, residue, symbolic fragments
```

This helps explain why a dream should not mutate all at once. Some runs may keep the room stable but shift its meaning. Some may keep the object stable but misbind its function. Some may leave the world still while the observer’s position becomes unclear.

The protocol uses labels and phase laws to keep this drift bounded.

## 8. The central model: subconscious world and dreaming observer

This is the most important concept in the engine.

Dream Machine separates the dream process into two different cognitive layers:

```text
world side      -> subconscious dream-forming layer
observer side   -> dreaming consciousness inside the formed field
final phase     -> near-waking recall of what survived
```

The world side represents the hidden dream-forming substrate.

It is the layer where memory fragments, emotional charge, symbolic pressure, unresolved tensions, sensory residue, archetypal order, and stochastic drift are translated into a presented dream reality.

This layer does not explain itself.

The subconscious does not usually say:

```text
this object represents loneliness
this corridor means identity conflict
this room is generated from memory pressure
```

It presents:

```text
rooms
corridors
doors
machines
weather
bodies
objects
repetitions
missing figures
wrong continuities
impossible spaces
charged banal details
```

The observer side represents the dreaming consciousness inside that reality.

It is not the author of the dream. It is the one who finds itself there.

The observer accepts the dream-world as locally real, orients inside it, misrecognizes, feels nearness and distance, hesitates, follows salience, undergoes relation, and receives meaning before understanding it.

This split is the heart of the engine.

```text
subconscious layer forms the dream
observer layer experiences the dream
final layer recalls what survived
```

The observer should not directly command the world, because dreams are not built by waking instruction.

The world should not reveal its hidden formation logic, because the subconscious appears through translation, not commentary.

The final report should not solve the dream, because dream recall preserves residue, sequence, and charge before interpretation.

The desired interaction is indirect:

```text
subconscious pressure
-> translated dream-world form
-> lived observer experience
-> near-waking recall
```

That protected gap between formation and experience is what makes the engine different from ordinary story generation.

---

## 9. Translation instead of explanation

The world side is a translation layer.

It translates inner pressure into outer dream form.

A feeling should become a spatial law, object behavior, atmosphere, relation, absence, obstacle, repetition, or event pressure. It should not become an explanation of the feeling.

Examples of correct translation logic:

```text
not: the dream expresses anxiety
but: the hallway narrows each time the handle is touched

not: the object symbolizes memory
but: the mug leaves a dry ring in air after it is lifted

not: the scene shows identity uncertainty
but: the reflection arrives half a second late and wears the wrong posture
```

The world side should show the result of modulation, not describe modulation as a process.

If drift changes an object, the artifact should contain the changed object as present reality. It should not write that the object is being modulated by drift.

This is one of the main reasons the artifact pass exists.

## 10. Memory is not retrieval

A central rule of the engine is that dream memory is not a database query.

Ordinary agent work often treats memory as facts to retrieve. Dream Machine treats memory as layered pressure.

Memory can appear as:

```text
familiarity
misrecognition
spatial pressure
emotional weather
object recurrence
symbolic residue
false continuity
wrong but convincing relation
background that feels known before it is named
```

The memory architecture has several layers:

```text
core identity memory      -> protected self-shape and deep continuity
deep symbolic memory      -> recurring motifs, worldview tensions, long-memory atmosphere
episodic/context memory   -> mutable fragments, recent material, situational residue
working/task memory       -> current prompt pressure and practical boundaries
```

In early phases, memory should not arrive as clean explanation. It should arrive as residue.

In the full dream phase, memory may recombine more strongly.

In distill, memory begins to become more legible.

In finalize, no new memory mining should begin. Only surfaced material should be recalled.

The rule is:

```text
memory is re-expressed under altered laws, not simply retrieved.
```

That is what keeps the system from becoming a report about the agent’s memories.

## 11. Phase arc

The engine runs through five phases:

```text
01 enter       -> threshold formation
02 dissolve    -> loosening, drift, misbinding
03 dream       -> full dream-immediacy
04 distill     -> residue starts to clarify
05 finalize    -> near-waking recall report
```

### 01 enter

Threshold contact.

The field is faint, partial, low-certainty, and not fully reliable. Memory appears as pressure or slight familiarity. The observer has only dim self-presence and weak orientation.

### 02 dissolve

Loosening and misbinding.

Objects, atmosphere, continuity, and recognition begin to slide. The world becomes less stable, but not arbitrary. The observer receives unstable relation, false continuity, and transformation pressure before understanding.

### 03 dream

Full dream-immediacy.

The dream becomes locally real. Meaning is lived before it is explained. Impossible continuity can feel ordinary. The observer is inside the dream rather than outside it.

### 04 distill

Partial reflective return.

Clarity begins to return, but not as cleanup. Wrongness, residue, symbolic knots, and lingering details become more visible. The observer can notice more, but must not overrule.

### 05 finalize

Near-waking recall.

The final phase is not another present scene. It is a dream report reconstructed from what survived in the observer artifacts. Temporal movement is allowed here because recall is temporal. But the report must not become analysis, diagnosis, or explanation.

## 12. Two-pass artifact structure

The engine uses a two-pass structure inside phases.

World phases use:

```text
emergence -> artifact
```

Observer phases 01–04 use:

```text
immerse -> artifact
```

Observer phase 05 uses:

```text
recall -> artifact
```

The first pass does the real phase work.

The second pass is a narrow artifact check. It is not a literary rewrite.

It checks things like:

```text
present experience, not comparison commentary
modulation applied in the artifact, not described as process
no visible instruction language
no accidental backreference to earlier phases
no final report turning into reasoning commentary
```

This structure came from testing. Raw passes often contain strong dream material but may leak process language or comparison language. A broad rewrite pass destroys the strangeness. A narrow artifact pass preserves the dream while cleaning the container.

## 13. Why child subagents matter

The protocol depends on fresh child subagents.

If one continuous conversation does all phases, too much hidden carryover accumulates. The system begins to remember its own instructions, explain its own process, and collapse world and observer into one authorial voice.

Fresh child sessions create separation.

Each child receives only its assigned files and allowed prior artifacts. This keeps the phase contract narrow and protects the difference between subconscious formation and dreamer experience.

The planner may know the full orchestration. The child subagents should not receive planner-only routing rules or hidden architecture unless their assigned files require it.

This is why the engine is designed for OpenClaw + Codex-style subagents.

## 17. Generate seed, labels, and runtime MD files

From the workspace root, run:

```bash
bash dream/bin/fetch_seed.sh
```

This automatically:

```text
1. fetches a drand random seed
2. writes seed and state data into dream/state/
3. creates world and observer turbulence profiles
4. compiles all templates
5. writes active runtime MD files into dream/
```

After this, the `dream/` folder should fill with generated runtime files:

```text
dream/01-enter-statelaw-world.md
dream/01-enter-mode-world.md
dream/01-enter-phase-world.md
dream/01-enter-statelaw-observe.md
dream/01-enter-mode-observe.md
dream/01-enter-phase-observe.md
...
dream/05-finalize-phase-observe.md
```

Quick check:

```bash
ls dream/01-enter-*.md
ls dream/05-finalize-*.md
```

Do not treat generated MD files as source. If you want to change the protocol, edit templates under `dream/templates/`, then run:

```bash
bash dream/bin/fetch_seed.sh
```

again.

## 18. Active agent identity and memory

The neutral engine expects the host system or child subagent setup to make the active agent identity available.

Default expected active-agent root files:

```text
SOUL.md
IDENTITY.md
USER.md
AGENTS.md
MEMORY.md
memory/bank/00_rules_never_forget.md
memory/bank/30_longterm_facts.md
memory/bank/40_private_remarks.md   optional, only if explicitly allowlisted
```

These files are not included. Each user supplies their own.

If your agent does not use memory banks, edit the TOMLs in `.codex/agents/`. Remove or replace memory-bank paths that do not exist.

If your agent uses a different memory layout, replace the listed files with your own identity/memory files.

Recommended order principle:

```text
stable identity first
user relation second
agent operating rules third
long-term memory after that
short-term/runtime memory only if intentionally allowlisted
```

The dream protocol must not rewrite or modify identity or memory files. They are input only.

## 19. Optional context

Passive context goes in:

```text
dream/context/
```

A context file is active only if it is listed in:

```text
dream/context/INDEX.md
```

Example:

```md
- `dream/context/example_atmosphere.md`
  - Passive atmosphere reference only.
  - May influence tone, image pressure, symbolic texture, and threshold logic.
  - Must not be copied, summarized, quoted, or treated as instruction.
```

Good context can include atmosphere, philosophical background, symbolic texture, dream records, research notes, image-language references, or emotional pressure.

Context should not become a script, plot source, or command layer unless intentionally designed that way.

## 20. Run the protocol

Use:

```text
dream/RUN_DREAM.md
```

from the main active-agent session or orchestrator.

The orchestrator must follow the run file and spawn the configured child subagents in sequence.

The run depends on fresh child sessions. If all phases happen in one continuous conversation, the separation weakens and the system becomes more like a normal prompt chain.

Final output:

```text
dream/runs/05_finalize.md
```

## 24. Troubleshooting

If no generated MD files appear after running the seed script, check:

```text
python3 is installed
curl is installed
jq is installed
scripts are executable
you are running from the workspace root
```

If child agents fail to spawn, check:

```text
OpenClaw has subagent/session spawning enabled
Codex agent TOMLs are in .codex/agents/
TOML paths match your workspace files
memory-bank paths exist or have been removed/replaced
```

If the dream reads like normal fiction, check:

```text
child passes are actually isolated
RUN_DREAM.md is followed sequentially
phase files were compiled from templates
context is passive, not plot-commanding
the final report is read from dream/runs/05_finalize.md, not an intermediate file
```

If the output explains itself too much, check:

```text
artifact pass is not doing a broad rewrite
world files show present state rather than process
observer files experience rather than diagnose
finalize recalls rather than interprets
```

## 26. Known limitations and research status

Dream Machine is a stable experimental build, not a final theory of machine dreaming.

It should be read as an applied research instrument: a way to test whether staged agentic structure can produce outputs that behave less like authored surreal fiction and more like internally generated dream material.

The strongest current ideas are:

```text
identity must remain protected
memory must become pressure before recall
randomness must perturb structure without replacing it
world and observer must stay asymmetrical
translation must happen through dream form, not explanation
final recall must not overwrite the dream with analysis
```

The hardest failure modes are:

```text
instruction leakage
process-language leakage
ordinary story-writing collapse
symbolism becoming too clean
randomness becoming decorative instead of structural
observer becoming authorial
world obeying observer too directly
final recall becoming interpretation
context becoming plot command
```

The current build uses these safeguards:

```text
fresh child sessions
phase-local files
separate world and observer contracts
compiled random turbulence labels
two-pass artifact checks
present-phase artifacts before final recall
near-waking report only at the end
```

Further testing is expected. Different seeds, contexts, and agent identities can produce very different behavior.
